# Plan 01-01 — Grading contract & shared zod schema

## Objective
Define ONE canonical, versioned contract for grading output, expressed as a zod schema with inferred TypeScript types, importable by both the Deno edge function and the React client. This is the foundation every other grading plan validates against. Replaces the three divergent ad-hoc shapes (`generate-grading-feedback`, `aiParser.ts`, `test-ai-grading`).

## Context
Per [../05-ai-grading-pipeline.md](../05-ai-grading-pipeline.md) the target schema has: `overall` (score/maxScore/letter?/confidence), `criteria[]` (name/weight/maxScore/score/level?/rationale/evidence{quote,startIndex,endIndex}/verified/confidence), `annotations[]` (quote/startIndex/endIndex/comment/type/matched), `summaryFeedback`, `flags[]`. Server-set fields (`verified`, `matched`, recomputed totals) must be representable but produced server-side, not trusted from the model.

<action>
Create `supabase/functions/_shared/grading-schema.ts` exporting a zod schema `GradingResultSchema` and `z.infer` type `GradingResult` with exactly these fields: `overall` { score:number, maxScore:number, letter:string optional, confidence:number 0-1 }; `criteria` array of { name:string, weight:number, maxScore:number, score:number, level:string optional, rationale:string, evidence:{ quote:string, startIndex:number, endIndex:number }, verified:boolean, confidence:number }; `annotations` array of { quote:string, startIndex:number, endIndex:number, comment:string, type: enum("praise","suggestion","error","question"), matched:boolean }; `summaryFeedback:string`; `flags:` array of string. Also export a `MODEL_OUTPUT` variant `GradingModelOutputSchema` that OMITS server-set fields (`overall.score` recompute, `criterion.verified`, `annotation.matched`) — i.e. what the model is allowed to return — and a constant `GRADING_SCHEMA_VERSION = "1"`. Import zod via a pinned esm.sh/deno-compatible URL consistent with other functions; do not add npm deps to the Deno runtime.
</action>
