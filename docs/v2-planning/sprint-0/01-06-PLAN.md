# Plan 01-06 — Eval harness + golden set + CI gate

## Objective
Stand up the regression harness that GATES the phase: a small golden set, deterministic + agreement scorers, a committed baseline, and a CI job that fails on regression. No grading prompt/model change ships unmeasured after this.

## Context
Per [../05-ai-grading-pipeline.md](../05-ai-grading-pipeline.md) and `prompt-evaluation-test-harness-skill` / `ai-grading-rubric-evaluation-skill`. There are currently zero tests; "92% accuracy" in `Training.tsx` is hardcoded fiction. The harness validates the 01-03 structured output against the 01-01 schema and against teacher-provided expected grades. Essays MUST be de-identified before entering the repo (FERPA — see [../06-supabase-security-review.md](../06-supabase-security-review.md)).

<title>Assemble the de-identified golden dataset (~15 cases)</title>

- docs/v2-planning/06-supabase-security-review.md  (de-identification requirement)

</read_first>
<action>
Create `evals/dataset/` with ~15 JSONL/JSON cases, each: `{ id, rubric (structured or text), essay (DE-IDENTIFIED — names/IDs stripped/replaced), expected: { overallScore, perCriterion?, sampleFeedback }, tags }`. Cover golden path + edge cases (off-topic, very short, very long, a prompt-injection case, a quote-heavy essay). Source expected grades from the teacher (this is the human-input step → `autonomous:false`). Add `evals/dataset/README.md` noting the de-identification rule and how to add cases from production disagreements.
</action>
<acceptance_criteria>
- `evals/dataset/` contains ≥15 cases, each with `essay`, `rubric`, and `expected` fields.
- No case contains a real student name/ID (spot-checkable; README states the rule).
- At least one case each is tagged `injection`, `off_topic`, `short`, `long`.
</acceptance_criteria>
</task>

<task id="01-06-2">
<title>Implement scorers (deterministic + teacher-agreement)</title>
<read_first>
- supabase/functions/_shared/grading-schema.ts  (schema to validate against)
- src/lib/annotations/resolveAnchors.ts  (for annotation-match-rate scorer)
- docs/v2-planning/05-ai-grading-pipeline.md  (scorer list incl. QWK)
</read_first>
<action>
Create `evals/scorers.ts` exporting: deterministic scorers — `schemaValid` (output passes `GradingResultSchema`), `evidenceFoundRate` (fraction of criteria with `verified:true`), `scoreInBounds` (every `criterion.score ≤ maxScore`), `annotationMatchRate` (fraction with `matched:true`); agreement scorers — `exactAgreement`, `withinOneLevel`, and `quadraticWeightedKappa` comparing predicted vs `expected` grades across the set. Each returns a numeric/boolean plus details.
</action>
<acceptance_criteria>
- `evals/scorers.ts` exports all named scorers above.
- Unit tests prove `quadraticWeightedKappa` returns 1.0 for identical vectors and ~0 for random, and `scoreInBounds` flags an out-of-bounds fixture.
</acceptance_criteria>
</task>

<task id="01-06-3">
<title>Runner, baseline, and CI gate</title>
<read_first>
- evals/scorers.ts  (from 01-06-2)
- evals/dataset/  (from 01-06-1)
- supabase/functions/generate-grading-feedback/index.ts  (the function under test)

<action>
Create `evals/run.ts` that loads the dataset, invokes the grading path for each case (temp 0; N runs per case to measure variance), applies all scorers, prints an aggregate report + per-tag breakdown + a diff vs `evals/baseline.json`, and exits non-zero if any scorer regresses below threshold or any case flips to failing. Add `npm run eval` and `npm run eval:baseline` (writes/updates `baseline.json`) scripts. Add `vitest` + `npm test` if absent. Commit an initial `evals/baseline.json`. Create `.github/workflows/eval.yml` running lint + typecheck + `npm test` + `npm run eval` on PRs, failing the build on eval regression. Use a test/sandbox model key via CI secret; never commit keys.
</action>
<acceptance_criteria>
- `npm run eval` runs end-to-end and prints aggregate + per-tag + diff-vs-baseline.
- `evals/baseline.json` is committed.
- `npm run eval` exits non-zero when a scorer is forced below threshold (verified by a temporary threshold bump).
- `.github/workflows/eval.yml` exists and runs typecheck + test + eval on PR; references the model key via CI secret, not a literal.
</acceptance_criteria>
</task>

## Verification

- Variance across N runs at temp 0 is reported (consistency check).
