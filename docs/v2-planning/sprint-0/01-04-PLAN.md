# Plan 01-04 — Robust annotation anchoring

## Objective
Make annotation anchoring reliable: consume the model's char offsets, validate them, fuzzy-match as fallback, and **never silently drop** an annotation. Unmatched comments must still surface so teachers never lose feedback.

## Context
Today `resolveAnchors.ts` locates each comment by exact `indexOf` on `c.text` (priority: `startIndex` → nth `occurrence` → first match) and **skips** comments not found verbatim. The prompt didn't request offsets, so anchoring relied on exact substring match — PDF whitespace normalization (`pages…join(' ')`), smart quotes, ellipses, or paraphrase silently delete the comment. As of 01-03 the model now returns `startIndex`/`endIndex` plus the `quote`, and annotations carry a `matched` flag.

<title>Anchor on offsets first, with validation</title>
<read_first>

<action>
Rewrite `resolveAnchors(essay, annotations)` to: (1) for each annotation, first trust `startIndex`/`endIndex` — validate that `essay.slice(startIndex,endIndex)` normalizes-equal to `quote`; if valid, use those offsets; (2) normalize both essay and quote (NFC, collapse whitespace, straighten smart quotes, strip surrounding ellipses) before comparison so PDF-extraction artifacts don't break valid matches. Preserve the existing `AnchorRange` output shape consumed by `splitIntoSpans`.
</action>
<acceptance_criteria>
- Given valid offsets, the resolved range maps to the intended span (unit test with a fixture).
- A quote differing only by whitespace/smart-quote/ellipsis from the essay still resolves (unit test).
- `splitIntoSpans` consumes the output unchanged (existing rendering tests still pass).
</acceptance_criteria>
</task>

<task id="01-04-2">
<title>Fuzzy fallback + never silent-drop</title>
<read_first>
- src/lib/annotations/resolveAnchors.ts  (after 01-04-1)
- src/lib/grading/types.ts  (matched flag)
- docs/v2-planning/05-ai-grading-pipeline.md  ("Anchor annotations" section)
</read_first>
<action>
When offset validation fails, fall back to: (a) normalized exact substring search; (b) a fuzzy/token-similarity search (e.g. best-window match above a similarity threshold). If a match is found, set `matched: true` with the located range. If no match clears the threshold, DO NOT discard — return the annotation with `matched: false` and no range so the UI can surface it in an "unplaced feedback" section. Add a returned summary count of matched vs unmatched. Remove the old "skip if not found" branch.
</action>
<acceptance_criteria>
- No code path discards an annotation (grep: the old skip/`continue`-on-not-found is gone).
- An annotation whose quote is absent from the essay is returned with `matched: false` (unit test).
- The function returns counts (e.g. `{ matched, unmatched }`) for the caller to display.
- Overlap resolution still produces non-overlapping rendered spans (existing behavior preserved).
</acceptance_criteria>
</task>
